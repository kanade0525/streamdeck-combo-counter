# 死活監視キー（Stream Deck プラグイン）仕様書

## これは何か

監視対象が落ちるとキーが赤くなり、**そのキーを押すと復旧処理が走る**。復旧したら自分で緑に戻る。
Stream Deck のボタンだけで完結する。

## なぜ作るか

`ping` を叩くだけならシェルで済む。このプラグインの存在理由は二つだけ。

1. **常駐して押していない間の履歴を持つ** — 押した瞬間の値ではなく、落ちていた事実と時間が残る
2. **見える場所と直す場所が同じ物体である** — 赤いキーを押せば復旧が走る。画面を見に行く動作が消える

この二つに当てはまらない機能は入れない。表示を増やす方向には広げない。

## 対象外（作らない）

- 複数キーにまたがる盤面グラフ。キーを消費する割に、1キーのスパークラインから増える情報が無い
- Stream Deck + のダイヤル。手元の機種はボタンのみ
- 外部サービスへの通知送信。**監視結果はこの端末から出さない**
- 監視対象の自動発見。対象は人が設定する

## 画面（キー1枚・72×72）

SVG を `setImage` で送る。`setTitle` は使わない（OSが文字を上に重ねて絵が崩れるため空にする）。

```
┌────────────┐
│ さくら本番      │  ← 名前（上部・小さく）
│    42ms      │  ← 現在値。障害中は連続失敗回数
│ ▁▂▃▅▃▂▁▁▂▃  │  ← 直近のスパークライン
└────────────┘
```

背景色が状態を表す。**色だけで状態が分かること**を最優先にし、数字は補助とする。

| 状態 | 背景 | 意味 | 押した時 |
| --- | --- | --- | --- |
| 正常 | 暗い緑 | 直近の応答が閾値以内 | **何もしない**（誤爆防止） |
| 疑い | 黄 | 1回以上失敗したが確定前 | 何もしない |
| 障害 | 赤 | 失敗が確定回数に達した | **長押しで復旧コマンド** |
| 復旧中 | 青（明滅） | 復旧コマンド実行中 | 何もしない（多重実行を防ぐ） |
| 未設定 | 灰 | 宛先が未入力 | 設定画面を促す |

正常時に押しても何も起きないのは意図的な設計。**押せる状態かどうかが押す前に見えている**ことがこの
プラグインの主張なので、いつでも押せてしまうとその主張が崩れる。

## 状態機械

```
正常 --(失敗1回)--> 疑い --(連続で確定回数に到達)--> 障害
疑い --(成功1回)--> 正常
障害 --(成功1回)--> 正常
障害 --(長押し)--> 復旧中 --(コマンド終了)--> 疑い（次の巡回を待つ）
```

- **失敗1回で赤にしない。** 瞬断で赤くなる監視は、赤が意味を失って見なくなる
- 復旧コマンドが終わっても即座に緑にしない。**成功を自分で確かめてから**緑に戻す

## 監視方式

| 方式 | 実装 | 使いどころ |
| --- | --- | --- |
| HTTPS | `fetch` で GET、ステータスと所要時間 | 公開サイト。既定 |
| TCP | `net.Socket` で接続できるか | DB やポートだけ開いている先 |
| ping | `/sbin/ping -c 1 -W` を1回 | ICMP しか通らない先 |

いずれも Node 標準のみ。**依存パッケージはゼロ**。

## 設定（Property Inspector）

| 項目 | 既定 | 備考 |
| --- | --- | --- |
| 表示名 | （空） | キーに出す短い名前 |
| 方式 | HTTPS | 上記3つ |
| 宛先 | （空） | URL / host:port / host |
| 間隔 | 30秒 | 最短5秒 |
| タイムアウト | 5秒 | |
| 障害確定の連続失敗回数 | 3 | |
| 応答が遅い判定 | 1000ms | 超えたら成功だが黄寄りの色にする |
| 復旧コマンド | （空） | 空なら押しても何も起きない |
| 長押し時間 | 1.5秒 | 復旧の発火に要する押下時間 |
| 落ちた時に通知 | ON | macOS の通知を1回だけ出す |

## 復旧コマンドの扱い

任意のシェルコマンドを実行できる以上、ここが唯一の危ない部分になる。

- 実行は**長押しでのみ**発火する。短押しでは絶対に走らない
- 実行中は状態を「復旧中」に固定し、**終わるまで再発火させない**
- コマンド文字列は設定に保存されるだけで、どこにも送らない
- 実行結果（終了コードと先頭数行）はログファイルにのみ残す

## 記録

- **直近の測定値はプラグインのプロセス内に持つ。** 別ページに切り替えている間も測定は続ける
- 障害の開始・終了時刻は `~/Library/Application Support/com.elgato.StreamDeck/Plugins/<uuid>/logs/` に追記
- どこにも送信しない

## 受け入れ条件

1. 対象を落として3巡回以内に赤くなり、上げると次の巡回で緑に戻る
2. 1回だけ失敗させた時に赤にならない（黄で止まる）
3. 正常時に押しても復旧コマンドが走らない
4. 障害時に短く押しても走らず、長押しでのみ走る
5. 復旧中にもう一度長押ししても二重に走らない
6. Stream Deck を再起動しても設定と障害履歴が残る
7. ページを別プロファイルに切り替えて戻しても、その間の測定が欠けていない

| 1 | 固定間隔で HTTPS を叩き、色だけ変える |  |

| 3 | 長押し判定と復旧コマンド |  |

段階0を先に通すのは、**SVG が Stream Deck のレンダラでそのまま出るかどうか**が最大の未確認事項で、
ここが駄目なら描画の設計を全部やり直す必要があるため。

## 流儀

- ビルドステップ無し。素の ES modules を `#!/usr/bin/env node` で直接起動する
- 依存パッケージゼロ。Node 24 の標準 `WebSocket` を使う
- コメント・UI文言は日本語。コメントは「何をしているか」ではなく「なぜこの方針か」を書く

## 確かめたこと（段階0・2026-09-15）

手元の環境（macOS 26.6.2 / Stream Deck 7.5.1 / Node 24.7 / Stream Deck 5×3）で実測した結果。

- **`CodePath` に `.mjs` を直接書くと Stream Deck は起動しない。** ログに
  `The plugin has no attached client` と出るだけで、プロセスは立ち上がらない。
  拡張子なしのシェルスクリプトを噛ませて node に渡すと起動する
- **Stream Deck から起動されると PATH が最小限になる。** `node` は絶対パスで指定する必要がある
- Node 24 の標準 `WebSocket` でそのまま繋がる。**公式SDKもビルドもパッケージも要らない**
- `setImage` に SVG（base64 の data URI）を渡すと**図形も文字も描かれる**。
  描画設計をSVG前提で進めてよい
- `willAppear` の payload に `coordinates`（列・行）が入る。複数キーの配置は取れる
- 標準出力は Stream Deck に捨てられる。**ログはファイルに書く以外に見る手段が無い**
